# Admin AI Prompt System

## Main Goal

The official admin content generation workflow is:

```text
Admin -> BatiBot Curriculum Intelligence API -> Gemini -> Validator -> Review -> Published
```

BatiBot is the source of truth. Gemini is only a draft assistant. Nothing generated by Gemini should become learner-facing content until the BatiBot validator and admin review flow pass.

## Module 1: Admin Intake

Prompt:

```text
You are receiving an admin request for unpublished BatiBot Play content. Require the admin selection to include gradeLevel, worldId, topicId, phase, node, assetId when needed, activity layout, reward XP, reward mapping, and unlock mapping. If the request is missing Play placement, treat the draft as incomplete and unsafe to publish.
```

Required fields:

- `gradeLevel`
- `worldId`
- `topicId`
- `phase`
- `node`
- `assetId`
- `questionTypes`
- `vocabularyMode`
- `rewardXp`
- `unlockRewardMapping`

## Module 2: BatiBot Curriculum Intelligence API Contract

Prompt:

```text
You are downstream from the BatiBot Curriculum Intelligence API. Treat the API contract as the source of truth for curriculum, Play-map destination, active learning phase, UI format, approved vocabulary, asset requirements, reward mapping, validation gates, and publishing rules.
```

The BatiBot Curriculum Intelligence API must resolve:

- grade and learner level
- world and topic
- competency trace when available
- selected active learning phase
- allowed child action
- allowed vocabulary
- required mobile UI surface
- image/audio/speech asset needs
- reward and Rank impact
- publish validation gates

Source files:

- `src/services/curriculumDraftApi.ts`
- `src/domain/rules/gemini-draft-rules.ts`

## Module 3: Gemini Draft Boundary

Prompt:

```text
You are generating an unpublished BatiBot admin draft. BatiBot owns the curriculum, Play-map placement, phase rules, UI format, safety checks, reward logic, and publishing decision. Gemini only assists with draft content.
```

Gemini must:

- return JSON only
- stay inside the BatiBot Curriculum Intelligence API contract
- avoid direct publishing claims
- avoid secrets, API keys, or deployment instructions
- avoid adult admin wording in learner-facing prompts
- include review metadata for every question

Gemini must not:

- invent new curriculum outside the selected world/topic
- introduce new content in `Practice` or `Challenge`
- create generic topic-label questions
- invent live image URLs
- mark the draft as safe or published

## Module 4: Rank / Play / Reward Alignment

Prompt:

```text
The learner app is Rank / Play / Reward. Learn and Quiz are internal Play actions. All generated content must appear as Play content mapped to Grade > World > Topic > Phase > Node, with Rank and Reward impact described structurally.
```

Admin output must show:

- where learners see it: `Play > World > Topic > Phase`
- XP impact
- star impact
- badge or achievement impact
- Rank progress
- Reward progress
- next unlock impact

## Module 5: Active Learning Phase Fit

Prompt:

```text
Use the selected BatiBot phase only: Discover, Explore, Interact, Practice, Challenge, Reward, Progress, or Mastery. Practice repeats known content with support. Challenge checks known content with less guidance and introduces no new content.
```

Phase rules:

- `Discover`: introduce one current target only.
- `Explore`: let the child observe known content with gentle support.
- `Interact`: guide one supported mini-action.
- `Practice`: repeat known content with support.
- `Challenge`: check known content with fewer hints and no new content.
- `Reward`: celebrate completion.
- `Progress`: show saved learner progress.
- `Mastery`: confirm mastery and next unlock.

## Module 6: Child Action And Mobile UI

Prompt:

```text
Every item must use one clear child action such as Tap, Match, Count, Say, Compare, Choose, or Complete. Use short child-facing copy, large-choice or matching surfaces, audio/speech controls when required, and no dense adult instructions.
```

UI rules:

- short prompts
- large touch targets
- no overlapping text
- no dense paragraphs
- visual/audio support for early grades
- exact asset mapping when available
- no hidden controls required for completion

## Module 7: Known Content And Asset Contract

Prompt:

```text
Use only the approved Learning Worlds word set, topic, asset contract, and competency context supplied by BatiBot. Image-based items must include an approved asset mapping or exact asset prompt for admin approval; do not invent live URLs.
```

Validator should block publishing when:

- image content needs an asset but no approved `assetId` exists
- the asset does not match the selected world/topic
- the content uses vocabulary outside the approved Learning Worlds word set
- the content lacks grade/world/topic/phase mapping

## Module 8: Validator And Review Metadata

Prompt:

```text
For every question, include sourceVocabularyWord, vocabularyUsed, targetSkill, reasoningType, questionIntent, quality scores, level-fit explanation, alignment notes, answer justification, distractor notes, and validation flags when risk exists.
```

Each generated item should support:

- phase fit review
- Practice safety review
- Challenge safety review
- asset match review
- mobile preview review
- reward/XP review
- unlock path review

## Module 9: Review Queue

Prompt:

```text
Return a draft for admin review. The admin review queue decides whether content is ready, needs assets, needs Play mapping, needs mobile preview, needs fixes, or can be published.
```

Review statuses:

- `draft`
- `ready-for-review`
- `needs-play-mapping`
- `needs-asset`
- `needs-mobile-preview`
- `needs-fix`
- `published`
- `archived`

## Module 10: Published Learner Effect

Prompt:

```text
Published content becomes visible only in the matching learner grade, Play world, topic, phase, and node. It may affect Rank XP, stars, Reward progress, badge/mastery state, and next unlocks.
```

User-side updates that apply:

- Play should retrieve published content only for the current learner grade/world/topic/phase.
- Play should show the content inside the matching phase, not as a separate quiz surface.
- Rank should reflect personal XP, stars, streak, mastery, and next goal changes from published content.
- Reward should reflect badges, achievements, stars, and unlock progress from published content.
- Learner copy should stay in Play / Rank / Reward language.
- Hidden Learn and Quiz routes should remain internal/deep-link surfaces only.

## Cleanup Rules

Replace:

- `Curated quizzes` with `Play Content` or `Learning Content`.
- `word bank` with `Learning Worlds word set` unless referring to the internal `wordBank` schema field.
- `quiz manager` with `Play Content Control Center`.
- standalone `Learn` and `Quiz` learner language with Play-internal wording.

Keep:

- legacy IDs that protect saved progress or unlock requirements.
- backend function security boundaries.
- admin-only Gemini access.
- validator blockers for phase, mapping, asset, preview, and reward safety.

Remove or avoid:

- old standalone vocabulary row targets as product goals.
- direct Gemini calls from client screens.
- learner-facing admin terminology.
- dense or adult-facing child prompts.
- generated content that bypasses review.
